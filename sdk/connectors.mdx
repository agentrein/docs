## Bring Your Own Client

AgentRein's SDK contains zero connector logic. There are no Stripe, GitHub,
or Slack classes to import from `agentrein`. Instead, you install and
initialize your own standard SDK clients as you normally would, then pass
them to `wrap()`.

<CodeGroup>
```ts TypeScript
import { AgentRein } from 'agentrein';
import { Octokit } from '@octokit/rest';
import { WebClient } from '@slack/web-api';
import Stripe from 'stripe';

const agentrein = new AgentRein({ apiKey: process.env.AGENTREIN_API_KEY });

// Your own clients — initialized with your own credentials
const octokit  = new Octokit({ auth: process.env.GITHUB_TOKEN });
const slack    = new WebClient(process.env.SLACK_TOKEN);
const stripe   = new Stripe(process.env.STRIPE_KEY);

const session = await agentrein.newSession({ agentId: 'my-agent', intent: '...' });

// Wrap once — use exactly as before
const agentOctokit = agentrein.wrap(octokit, session, { connector: 'github' });
const agentSlack   = agentrein.wrap(slack,   session, { connector: 'slack' });
const agentStripe  = agentrein.wrap(stripe,  session, { connector: 'stripe' });

await agentOctokit.issues.create({ owner: 'my-org', repo: 'my-repo', title: 'Task' });
await agentSlack.chat.postMessage({ channel: '#ops', text: 'Issue created' });
await agentStripe.invoices.create({ customer: 'cus_123' });
```

```python Python
import os
from agentrein import AgentRein
from github import Github
from slack_sdk import WebClient
import stripe

agentrein = AgentRein(api_key=os.environ["AGENTREIN_API_KEY"])

# Your own clients — initialized with your own credentials
gh = Github(os.environ["GITHUB_TOKEN"])
repo = gh.get_repo("my-org/my-repo")
slack = WebClient(token=os.environ["SLACK_TOKEN"])
stripe.api_key = os.environ["STRIPE_KEY"]

session = agentrein.new_session(agent_id="my-agent", intent="...")

# Wrap once — use exactly as before
agent_repo  = agentrein.wrap(repo,  session, connector="github")
agent_slack = agentrein.wrap(slack, session, connector="slack")

agent_repo.create_issue(title="Task")
agent_slack.chat_postMessage(channel="#ops", text="Issue created")
```
</CodeGroup>

## How the Proxy Works

`wrap()` returns a proxy that is transparent to your code — types,
autocompletion, and runtime behavior are all preserved. When you call any
method on the wrapped client:

1. The proxy captures the method path and arguments
2. Your original SDK method executes normally
3. AgentRein logs the action to the backend
4. If the call throws, AgentRein triggers a LIFO rollback of all previous
   actions in the session

<Info>
In TypeScript, step 3 is fire-and-forget (non-blocking). In Python (v1, synchronous), this logging call completes before `wrap()` returns.
</Info>

<Warning>
**Python-specific:** wrap the specific object whose methods you're about to call directly, not a top-level client several calls away. Many Python SDKs (unlike their JS counterparts) return a new, unwrapped object from factory/getter methods (`get_repo()`, `get_channel()`, etc.) — calls made on an object returned by a wrapped method are not automatically tracked. If your workflow needs to track a multi-step chain, wrap the specific resource object right before you start calling logged methods on it (see the GitHub example above, which wraps `repo`, not `gh`).
</Warning>

## Connector Prefix

The `connector` string you pass to `wrap()` must match the prefix used in
the AgentRein backend rollback registry. The supported prefixes are:

| Prefix | External SDK (TypeScript) | External SDK (Python) |
|---|---|---|
| `github` | `@octokit/rest` | `PyGithub` |
| `slack` | `@slack/web-api` | `slack_sdk` |
| `stripe` | `stripe` | `stripe` |
| `hubspot` | axios (REST) | `httpx`/`requests` (REST) |
| `salesforce` | axios (REST) | `simple-salesforce` |
| `notion` | axios (REST) | `httpx`/`requests` (REST) |
| `gmail` | `googleapis` | `google-api-python-client` |
| `gdrive` | `googleapis` | `google-api-python-client` |
| `gsheets` | `googleapis` | `google-api-python-client` |

For services not in this list, `wrap()` still logs actions, but no built-in
rollback strategy is available. See [Execution Methods](/sdk/call) for details.

## GitHub Connector Actions

The `github` connector supports 20 actions grouped by resource:

### Files
| Action | Description / Rollback Behavior |
|---|---|
| `github.files.create` | Create a repository file. Rollback deletes the created file. |
| `github.files.update` | Update a repository file. Rollback restores content from `beforeState`. |
| `github.files.delete` | Delete a repository file. Rollback recreates file content from `beforeState`. |

### Issues & Comments
| Action | Description / Rollback Behavior |
|---|---|
| `github.issues.create` | Create an issue. Rollback closes the issue. |
| `github.issues.update` | Update an issue. Rollback restores fields from `beforeState`. |
| `github.issues.lock` | Lock an issue. Rollback unlocks the issue. |
| `github.issueComments.create` | Create an issue comment. Rollback deletes the comment. |

### Pull Requests & Comments
| Action | Description / Rollback Behavior |
|---|---|
| `github.pullRequests.update` | Update a pull request. Rollback restores title, body, and state from `beforeState`. |
| `github.pullRequests.close` | Close a pull request. Rollback reopens the pull request. |
| `github.pullRequests.reopen` | Reopen a pull request. Rollback closes the pull request. |
| `github.pullRequests.merge` | Merge a pull request. **Non-reversible** — no automatic rollback (requires human approval). |
| `github.pullRequestComments.update` | Update a PR comment. Rollback restores comment body from `beforeState`. |

### Releases
| Action | Description / Rollback Behavior |
|---|---|
| `github.releases.create` | Create a release. Rollback deletes the created release. |
| `github.releases.update` | Update a release. Rollback restores name, body, and tag from `beforeState`. |
| `github.releases.delete` | Delete a release. **Non-reversible** — no automatic rollback (requires human approval). |

### Reviews
| Action | Description / Rollback Behavior |
|---|---|
| `github.reviews.create` | Submit a pull request review. **Non-reversible** — no automatic rollback (requires human approval). |

### Workflows
| Action | Description / Rollback Behavior |
|---|---|
| `github.workflows.enable` | Enable a workflow. Rollback disables the workflow. |
| `github.workflows.disable` | Disable a workflow. Rollback enables the workflow. |
| `github.workflows.dispatch` | Dispatch a workflow run. **Non-reversible** — no automatic rollback (requires human approval). |

### Users
| Action | Description / Rollback Behavior |
|---|---|
| `github.users.invite` | Invite a user to an organization. Rollback cancels the pending invitation. |

## Slack Connector Actions

The `slack` connector supports 23 actions grouped by resource:

### Messages
| Action | Description / Rollback Behavior |
|---|---|
| `slack.chat.postMessage` | Post a chat message. Rollback updates the message to a Tombstone (`⚠️ Reverted by AgentRein: [reason]`) and clears all blocks and attachments. |
| `slack.chat.update` | Update a chat message. Rollback restores content, blocks, attachments, and file IDs from `beforeState`. |
| `slack.chat.delete` | Delete a chat message. Rollback re-posts original text from `beforeState` with a restoration notice (best-effort text restoration only — thread replies and reactions are not restored). |

### Channels
| Action | Description / Rollback Behavior |
|---|---|
| `slack.channels.create` | Create a public or private channel. Rollback archives the created channel. |
| `slack.channels.rename` | Rename a channel. Rollback restores the previous channel name from `beforeState`. |
| `slack.channels.setTopic` | Set a channel's topic. Rollback restores the previous topic from `beforeState`. |
| `slack.channels.setPurpose` | Set a channel's purpose. Rollback restores the previous purpose from `beforeState`. |
| `slack.channels.archive` | Archive a channel. Rollback unarchives the channel. |
| `slack.channels.invite` | Invite users to a channel. Rollback kicks the invited users from the channel. |
| `slack.channels.kick` | Remove a user from a channel. Rollback re-invites the user to the channel. |
| `slack.channels.join` | Join a channel. Rollback leaves the channel. |
| `slack.channels.leave` | Leave a channel. Rollback re-joins the channel. |
| `slack.channels.close` | Close a direct message or group channel. Rollback opens the channel. |
| `slack.channels.open` | Open a direct message or group channel. Rollback closes the channel. |

### Files
| Action | Description / Rollback Behavior |
|---|---|
| `slack.files.upload` | Upload a file. Rollback deletes the uploaded file. |
| `slack.files.delete` | Delete a file. **Non-reversible** — no automatic rollback (requires human approval). |

### Reactions
| Action | Description / Rollback Behavior |
|---|---|
| `slack.reactions.add` | Add a reaction to an item. Rollback removes the reaction. |

### Stars
| Action | Description / Rollback Behavior |
|---|---|
| `slack.stars.add` | Add a star to an item. Rollback removes the star. |

### User Profile
| Action | Description / Rollback Behavior |
|---|---|
| `slack.userProfile.update` | Update a user's profile fields. Rollback restores previous profile fields from `beforeState`. |

### User Groups
| Action | Description / Rollback Behavior |
|---|---|
| `slack.userGroups.create` | Create a user group. Rollback disables the user group. |
| `slack.userGroups.update` | Update a user group's name, handle, or description. Rollback restores previous values from `beforeState`. |
| `slack.userGroups.users.update` | Update the list of users in a user group. Rollback restores the previous member list from `beforeState`. |
| `slack.userGroups.enable` | Enable a user group. Rollback disables the user group. |
| `slack.userGroups.disable` | Disable the user group. Rollback enables the user group. |

## Gmail Connector Actions

The `gmail` connector supports 16 actions grouped by resource:

<Note>
Gmail distinguishes soft-deletion (`trash`/`untrash`), which moves items to the Trash folder and is recoverable for 30 days, from permanent deletion (`delete`). It is recommended to use `trash` and `untrash` for safe, reversible message and thread management.
</Note>

### Messages
| Action | Description / Rollback Behavior |
|---|---|
| `gmail.messages.send` | Send an email message. Rollback sends a follow-up correction/disregard message in the thread. |
| `gmail.messages.reply` | Reply to an email thread. Rollback sends a follow-up correction/disregard message in the thread. |
| `gmail.messages.trash` | Move a message to trash (soft delete). Rollback untrashes the message. |
| `gmail.messages.untrash` | Remove a message from trash. Rollback moves the message back to trash. |
| `gmail.messages.markAsRead` | Mark a message as read. Rollback restores the `UNREAD` label. |
| `gmail.messages.markAsUnread` | Mark a message as unread. Rollback removes the `UNREAD` label. |
| `gmail.messages.delete` | Permanently delete a message. **Non-reversible** — no automatic rollback (requires human approval). |

### Drafts
| Action | Description / Rollback Behavior |
|---|---|
| `gmail.drafts.create` | Create a draft. Rollback deletes the created draft. |
| `gmail.drafts.delete` | Delete a draft. Rollback recreates the draft content from `beforeState` (preserving thread association if applicable). |

### Threads
| Action | Description / Rollback Behavior |
|---|---|
| `gmail.threads.modify` | Modify labels on a thread. Rollback restores previous label IDs from `beforeState`. |
| `gmail.threads.trash` | Move an entire thread to trash (soft delete). Rollback untrashes the thread. |
| `gmail.threads.untrash` | Remove an entire thread from trash. Rollback moves the thread back to trash. |
| `gmail.threads.delete` | Permanently delete a thread. **Non-reversible** — no automatic rollback (requires human approval). |

### Labels
| Action | Description / Rollback Behavior |
|---|---|
| `gmail.labels.create` | Create a label. Rollback deletes the created label. |
| `gmail.labels.modify` | Modify labels on a message. Rollback restores previous label IDs from `beforeState`. |
| `gmail.labels.delete` | Delete a label. **Non-reversible** — no automatic rollback (requires human approval). |
