## Bring Your Own Client

AgentRein's SDK contains zero connector logic. There are no Stripe, GitHub,
or Slack classes to import from `agentrein`. Instead, you install and
initialize your own standard SDK clients as you normally would, then pass
them to `wrap()`.

<CodeGroup>
```ts TypeScript
import { AgentRein } from 'agentrein';
import { Octokit } from '@octokit/rest';
import { WebClient } from '@slack/web-api';
import Stripe from 'stripe';

const agentrein = new AgentRein({ apiKey: process.env.AGENTREIN_API_KEY });

// Your own clients — initialized with your own credentials
const octokit  = new Octokit({ auth: process.env.GITHUB_TOKEN });
const slack    = new WebClient(process.env.SLACK_TOKEN);
const stripe   = new Stripe(process.env.STRIPE_KEY);

const session = await agentrein.newSession({ agentId: 'my-agent', intent: '...' });

// Wrap once — use exactly as before
const agentOctokit = agentrein.wrap(octokit, session, { connector: 'github' });
const agentSlack   = agentrein.wrap(slack,   session, { connector: 'slack' });
const agentStripe  = agentrein.wrap(stripe,  session, { connector: 'stripe' });

await agentOctokit.issues.create({ owner: 'my-org', repo: 'my-repo', title: 'Task' });
await agentSlack.chat.postMessage({ channel: '#ops', text: 'Issue created' });
await agentStripe.invoices.create({ customer: 'cus_123' });
```

```python Python
import os
from agentrein import AgentRein
from github import Github
from slack_sdk import WebClient
import stripe

agentrein = AgentRein(api_key=os.environ["AGENTREIN_API_KEY"])

# Your own clients — initialized with your own credentials
gh = Github(os.environ["GITHUB_TOKEN"])
repo = gh.get_repo("my-org/my-repo")
slack = WebClient(token=os.environ["SLACK_TOKEN"])
stripe.api_key = os.environ["STRIPE_KEY"]

session = agentrein.new_session(agent_id="my-agent", intent="...")

# Wrap once — use exactly as before
agent_repo  = agentrein.wrap(repo,  session, connector="github")
agent_slack = agentrein.wrap(slack, session, connector="slack")

agent_repo.create_issue(title="Task")
agent_slack.chat_postMessage(channel="#ops", text="Issue created")
```
</CodeGroup>

## How the Proxy Works

`wrap()` returns a proxy that is transparent to your code — types,
autocompletion, and runtime behavior are all preserved. When you call any
method on the wrapped client:

1. The proxy captures the method path and arguments
2. Your original SDK method executes normally
3. AgentRein logs the action to the backend
4. If the call throws, AgentRein triggers a LIFO rollback of all previous
   actions in the session

<Info>
In TypeScript, step 3 is fire-and-forget (non-blocking). In Python (v1, synchronous), this logging call completes before `wrap()` returns.
</Info>

<Warning>
**Python-specific:** wrap the specific object whose methods you're about to call directly, not a top-level client several calls away. Many Python SDKs (unlike their JS counterparts) return a new, unwrapped object from factory/getter methods (`get_repo()`, `get_channel()`, etc.) — calls made on an object returned by a wrapped method are not automatically tracked. If your workflow needs to track a multi-step chain, wrap the specific resource object right before you start calling logged methods on it (see the GitHub example above, which wraps `repo`, not `gh`).
</Warning>

## Connector Prefix

The `connector` string you pass to `wrap()` must match the prefix used in
the AgentRein backend rollback registry. The supported prefixes are:

| Prefix | External SDK (TypeScript) | External SDK (Python) |
|---|---|---|
| `github` | `@octokit/rest` | `PyGithub` |
| `slack` | `@slack/web-api` | `slack_sdk` |
| `stripe` | `stripe` | `stripe` |
| `hubspot` | axios (REST) | `httpx`/`requests` (REST) |
| `salesforce` | axios (REST) | `simple-salesforce` |
| `notion` | axios (REST) | `httpx`/`requests` (REST) |
| `gmail` | `googleapis` | `google-api-python-client` |
| `gdrive` | `googleapis` | `google-api-python-client` |
| `gsheets` | `googleapis` | `google-api-python-client` |

For services not in this list, `wrap()` still logs actions, but no built-in
rollback strategy is available. See [Execution Methods](/sdk/call) for details.

## Stripe Connector Actions

<Note>
Stripe actions involving direct financial movement (charges, refunds) or permanent account changes (customer/coupon deletion, payment method detachment) are treated conservatively in this connector — several are non-reversible by design, reflecting real constraints in Stripe's own API rather than a limitation of this integration.
</Note>

### Invoices
| Action | Description / Rollback Behavior |
|---|---|
| `stripe.invoices.create` | Create a draft invoice. Rollback deletes the draft invoice (if already finalized, requires manual intervention via Void or Credit Note). |

### Customers
| Action | Description / Rollback Behavior |
|---|---|
| `stripe.customers.create` | Create a customer object. Rollback deletes the created customer. |
| `stripe.customers.delete` | Permanently delete a customer and cancel their active subscriptions. **Non-reversible** — Stripe provides no restore endpoint. |

### Charges & Refunds
| Action | Description / Rollback Behavior |
|---|---|
| `stripe.charges.create` | Create a charge. **Non-reversible** — Stripe charges cannot be deleted, voided, or cancelled via the API. Reversing a charge's effect requires a separate, explicitly human-approved `stripe.refunds.create` action; this is never triggered automatically. |
| `stripe.refunds.create` | Create a refund against a charge or payment intent. **Non-reversible** — refunds are irreversible on Stripe and require explicit human approval before execution. |

### Coupons
| Action | Description / Rollback Behavior |
|---|---|
| `stripe.coupons.create` | Create a coupon. Rollback deletes the created coupon (prevents future redemptions; does not affect customers who already redeemed it). |
| `stripe.coupons.delete` | Permanently delete a coupon. **Non-reversible** — Stripe provides no restore endpoint for deleted coupons. |

### Meter Events
| Action | Description / Rollback Behavior |
|---|---|
| `stripe.meterEvents.create` | Record a usage-based billing event. Rollback attempts cancellation via a meter event adjustment, but this only succeeds within 24 hours of the original event; past that window, rollback will fail (this is expected Stripe platform behavior, not a bug). |

### Payment Methods
| Action | Description / Rollback Behavior |
|---|---|
| `stripe.paymentMethods.attach` | Attach a payment method to a customer. Rollback detaches the payment method. |
| `stripe.paymentMethods.detach` | Detach a payment method from a customer. **Non-reversible** — per Stripe's API, a detached payment method can never be re-attached to any customer. |
