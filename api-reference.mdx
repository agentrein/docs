## Shared REST Conventions

### Response Envelope

All successful REST API responses return HTTP 200/201 wrapped in a standard JSON envelope:

```json
{
  "data": { ... },
  "error": null,
  "timestamp": "2026-10-10T12:00:00.000Z"
}
```

### Error Responses (RFC 7807)

API errors return standard HTTP status codes (400, 403, 404, 409, 429, 500, 503) using the RFC 7807 Problem Details envelope:

```json
{
  "data": null,
  "error": {
    "type": "https://agentrein.com/errors/operator-required",
    "title": "Operator Credentials Required",
    "status": 403,
    "detail": "This endpoint requires a dashboard login token; API-key tokens cannot call it."
  },
  "timestamp": "2026-10-10T12:00:00.000Z"
}
```

#### SDK Error Mapping

AgentRein SDKs (TypeScript and Python) classify errors into typed exceptions:
- **Server Decisions (HTTP 401, 403, 409, 429)**: Always raised as `AgentReinDeniedError` carrying `status`, `errorType`, and `detail`. Under `failureMode: 'open'`, server denials are **never** fallen open.
- **Server Outages & Network Disconnects (HTTP 5xx, socket timeouts, DNS failure)**: Raised as `AgentReinUnavailableError`. Under `failureMode: 'open'`, outages fall open with a warning log.

Common RFC 7807 problem types:
- `agent-paused` (403): Agent is registered with status `'paused'`.
- `policy-blocked` (403): Action blocked by organizational policy.
- `plan-required` (403): Feature requires plan upgrade.
- `quota-exceeded` (403): Monthly action quota reached.
- `subscription-inactive` (403): Organization subscription is inactive or past due.
- `conflict` (409): State machine conflict or concurrent rollback.
- `rate-limit-exceeded` (429): Endpoint rate limit exceeded.

## System & Health Endpoints

### `GET /health`

Service health check endpoint.

- **Auth**: None required (Public)
- **Response**: `{ "status": "ok", "timestamp": "2026-10-10T12:00:00.000Z" }`

### `POST /webhooks/paddle`

Paddle billing subscription webhook endpoint.

- **Auth**: None required (Public; HMAC signature verified, Rate Limit: 300/min)
- **Response**: `{ "received": true }`

## Authentication & Tokens

AgentRein endpoints distinguish between **Agent API Keys** (`ar_live_...` / `ar_test_...`) and **Dashboard Operator Tokens**.

### `POST /auth/token`

Exchange an API key for a Bearer JWT token.

- **Auth**: None required (Public, Rate Limit: 60/min)
- **Body**: `{ "apiKey": "ar_live_..." }`
- **Response**: `{ "data": { "token": "eyJhbG..." } }`

### `POST /auth/register`

Register a new operator account and organization.

- **Auth**: None required (Public, Rate Limit: 20/15min)
- **Body**: `{ "email": "admin@example.com", "password": "...", "name": "Admin" }`
- **Response**: Returns created user and organization tokens (`201 Created`).

### `POST /auth/login`

Authenticate operator credentials with email and password.

- **Auth**: None required (Public, Rate Limit: 20/15min)
- **Body**: `{ "email": "admin@example.com", "password": "..." }`
- **Response**: Returns session JWT token.

### `POST /auth/forgot-password`

Send a password reset link to a registered email address.

- **Auth**: None required (Public, Rate Limit: 20/15min)
- **Body**: `{ "email": "user@example.com" }`
- **Response**: Confirmation message.

### `POST /auth/reset-password`

Reset operator account password using a reset token.

- **Auth**: None required (Public, Rate Limit: 20/15min)
- **Body**: `{ "token": "...", "newPassword": "..." }`
- **Response**: Password reset confirmation.

### `GET /auth/verify-email`

Verify operator email address using a verification token query parameter.

- **Auth**: None required (Public, Rate Limit: 20/15min)
- **Query**: `?token=...`
- **Response**: `{ "verified": true, "email": "user@example.com" }`

### `GET /auth/google`

Initiate Google OAuth2 operator sign-in flow.

- **Auth**: None required (Public)
- **Response**: Redirects to Google consent screen.

### `GET /auth/google/callback`

Google OAuth2 redirect callback receiver.

- **Auth**: None required (Public)
- **Response**: Redirects to dashboard with session token.

### `GET /auth/github`

Initiate GitHub OAuth2 operator sign-in flow.

- **Auth**: None required (Public)
- **Response**: Redirects to GitHub consent screen.

### `GET /auth/github/callback`

GitHub OAuth2 redirect callback receiver.

- **Auth**: None required (Public)
- **Response**: Redirects to dashboard with session token.

## Session Management Endpoints

### `POST /sessions`

Create a new safety session.

- **Auth**: API Key or Operator Token
- **Body**:
  ```json
  {
    "agentId": "billing-agent",
    "intent": "Process monthly subscription renewals"
  }
  ```
- **Response**: Returns created `Session` object (`201 Created`).
- **Errors**:
  - `403 Agent Paused`: If registered agent has status `paused` (`agent-paused`).

### `GET /sessions`

List sessions for the organization.

- **Auth**: Operator Token
- **Response**: Array of session objects enriched with:
  - `displayStatus`: Dynamic status (`ACTIVE`, `COMPLETED`, `ABANDONED`, `AWAITING_APPROVAL`, `ROLLING_BACK`, `REVERTED`, `PARTIALLY_REVERTED`, `ROLLBACK_FAILED`)
  - `counters`: Status summary count breakdown (`success`, `failed`, `pendingApproval`, `cleared`, `rolledBack`, `rollbackFailed`)
  - `simulated`: Boolean indicating if session ran in sandbox mode
  - `allowedCommands`: `{ "rollbackSession": boolean }`

### `GET /sessions/:id`

Retrieve details for a single session, including all logged actions and snapshots.

- **Auth**: API Key or Operator Token
- **Response**: Single session object with `actions` array and computed `displayStatus`, `counters`, `simulated`, and `allowedCommands`. Each action in `actions` includes `allowedCommands: { "retryUndo": boolean }` (true only for operator tokens on retryable actions).

### `PATCH /sessions/:id`

Mark a session as `COMPLETED`.

- **Auth**: API Key or Operator Token
- **Body**: `{ "status": "COMPLETED" }`
- **Errors**:
  - `400 Bad Request`: If `status` is not `'COMPLETED'` or session is not active/abandoned.
  - `409 Conflict`: If status transition conflict occurs.

### `POST /sessions/:id/rollback`

Trigger LIFO rollback compensation for all logged actions in a session.

- **Auth**: API Key or Operator Token
- **Errors**:
  - `409 Conflict`: If session cannot be rolled back (e.g. already `REVERTED` or no `SUCCESS` actions).

## Action Interception Endpoints

### `POST /sessions/:id/actions/precapture`

Capture pre-mutation resource state before executing a tool call.

- **Auth**: API Key or Operator Token (Rate Limit: 120/min)
- **Body**: `{ "apiName": "github.issues.update", "payload": { ... } }`
- **Response**: `{ "data": { "precaptureId": "snap_123", "captureFailed": false } }`

### `POST /sessions/:id/actions`

Log an action during or after execution.

- **Auth**: API Key or Operator Token
- **Body**:
  ```json
  {
    "apiName": "stripe.customers.create",
    "operationType": "CREATE",
    "payload": { "email": "user@example.com" },
    "response": { "id": "cus_123" },
    "status": "SUCCESS",
    "precaptureId": "snap_123"
  }
  ```
- **Errors**:
  - `403 Blocked by Policy`: If a policy with `BLOCK` matches (`policy-blocked`).
  - `403 Upgrade Required`: If approval gate triggered on `FREE` plan (`plan-required`).
  - `429 Quota Exceeded`: Monthly action limit reached (`quota-exceeded`).

### `PATCH /sessions/:id/actions/:actionId`

Update status or response payload of an existing action (used to confirm execution of `CLEARED` or `PENDING_APPROVAL` actions).

- **Auth**: API Key or Operator Token
- **Body**: `{ "status": "SUCCESS", "response": { ... } }`
- **Errors**:
  - `409 Conflict`: If invalid status transition is requested (e.g. patching `SUCCESS` to `PENDING_APPROVAL`).

### `POST /sessions/:id/actions/:actionId/rollback`

Roll back a single action within a session.

- **Auth**: Operator Token

### `POST /sessions/:id/actions/:actionId/retry-undo`

Retry undo compensation for a failed action rollback.

- **Auth**: Operator Token (API-key tokens get 403)
- **Preconditions**: Retryable only when action status is `ROLLBACK_FAILED` and its undo status is `FAILED`, the session is not sandbox, and the action's connector action has an automated undo strategy.
- **Responses**:
  - `200`: Updated action (both when the retry succeeds, action becomes `ROLLED_BACK` with undo `UNDONE`, and when it fails again, action stays `ROLLBACK_FAILED` with undo `FAILED`).
  - `202`: Current action when the provider call succeeded but recording the result failed (action stays `ROLLBACK_FAILED`, undo `IN_PROGRESS`; the system recovers the marker automatically after about 15 minutes; do not retry until status updates).
  - `404`: Session or action not found.
  - `409`: Not retryable or another retry in progress.
  - `422`: No automated undo strategy.
- **Note**: A successful retry moves the session from `FAILED` to `ROLLED_BACK` only if no `SUCCESS`, `PENDING_APPROVAL`, `CLEARED`, `DECLINED` or `ROLLBACK_FAILED` action remains. It does not resume the interrupted rollback; actions the halted chain never reached stay `SUCCESS` until the operator calls session rollback again. Each retry uses a fresh attempt id. The retry path sends no email.

## Approval Endpoints (HITL)

### `GET /approvals`

List approval requests (default filter: `PENDING`; optional `?status=PENDING|APPROVED|REJECTED|ALL`).

- **Auth**: Operator Token (`PRO` plan required)
- **Response**: Array of approval objects including `actionStatus`, `unconfirmed`, `payloadSummary`, and `timeRemaining`.

### `GET /approvals/:id`

Get single approval details including full action payload and snapshot.

- **Auth**: API Key or Operator Token

### `POST /approvals/:id/approve`

Approve a pending approval request.

- **Auth**: Operator Token (`PRO` plan required)

### `POST /approvals/:id/reject`

Reject a pending approval request.

- **Auth**: Operator Token (`PRO` plan required)
- **Body**: `{ "reason": "Unusual refund amount" }`

## Registry & Connector Validation

### `GET /registry`

Fetch connector registry metadata and action definitions.

- **Auth**: API Key or Operator Token
- **Response**: Array of connector actions with definitions, supported operations, and precapture requirements.

### `GET /settings/credentials/validate`

Validate configured connector credentials for agent operations.

- **Auth**: API Key or Operator Token (Rate Limit: 30/min)
- **Query**: `?connectors=github,slack,stripe`
- **Response**: `{ "valid": true, "configured": [...], "missing": [...], "suggestions": [...] }`

## SDK Execution Primitives

### `wrap<T>`

Wraps any standard SDK client instance to enable automatic side-effect logging, policy enforcement, and LIFO rollback.

```ts
declare function wrap<T extends object>(client: T, session: Session, options: WrapOptions): T;
```

`WrapOptions` specification:
```ts
interface WrapOptions {
  connector: string;            // Required connector identifier (e.g. 'github', 'slack', 'stripe')
  requiresApproval?: string[];   // Method paths requiring pre-execution approval
  retryable?: string[];          // Method paths eligible for exponential backoff retry
  pollIntervalMs?: number;       // Polling interval for approval checks (min 1000ms, default 2000ms)
  timeoutMs?: number;            // Timeout for approval checks (min 5000ms, default 86400000ms)
}
```
